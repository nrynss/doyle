Doyle compiles as a single Rust binary named `doyle`. It acts as a truth-maintenance system for coding agent memory.

The architecture separates into three primary layers. Four evidence sources feed change facts from the left. Two memory adapters connect external storage on the right. The core truth-maintenance engine coordinates state in the center.

Below the core, Meta models handle curation and semantic re-check tasks. Two runtime surfaces expose Doyle to operators and developer agents.

## The Shape of Doyle

Doyle decouples evidence generation from memory storage. The core coordinates truth maintenance without knowing how adapters store memories.

Four evidence sources extract stable elements and change facts:

1. **API contracts:** Parsed by [`src/contract.rs`](https://github.com/nrynss/doyle/blob/main/src/contract.rs) using Vimanam. Produces `ve2_` element identifiers and `vc2_` change facts.
2. **Legacy COBOL:** Parsed by [`src/evidence/legacy/mod.rs`](https://github.com/nrynss/doyle/blob/main/src/evidence/legacy/mod.rs). Produces `le2_` element identifiers and `lc2_` change facts.
3. **Console screens:** Read by `muse-wonder-1.0` via [`src/evidence/screens/mod.rs`](https://github.com/nrynss/doyle/blob/main/src/evidence/screens/mod.rs). Produces `se2_` element identifiers and `sc2_` change facts.
4. **Differential runs:** Executed by [`src/evidence/diffrun.rs`](https://github.com/nrynss/doyle/blob/main/src/evidence/diffrun.rs). Attributes output mismatches to executed paragraphs with `lc2_` change facts.

Memory adapters implement the `MemoryAdapter` trait. They read memories, write fresh notes, annotate stale claims, and apply human-approved corrections. Doyle provides built-in adapters for Muse Code memory files and Lambo graph databases.

Two runtime surfaces close the loop:

- **`doyle guard`:** Inspects tool inputs in Muse Code hooks before commands run. It holds operations that touch flagged elements without calling a model.
- **`doyle serve`:** Runs a local web dashboard. Reviewers inspect open flags, evaluate model proposals, and record sign-off decisions.

## The Core Model

The core data structures live in [`src/core/model.rs`](https://github.com/nrynss/doyle/blob/main/src/core/model.rs). Every command and subsystem relies on these types:

- **`ElementId`:** A stable identifier for a cited entity. Prefixes identify the source family: `ve2_` for contracts, `le2_` for COBOL programs, and `se2_` for terminal screens.
- **`MemoryRef`:** Identifies an external memory. Combines an adapter name such as `muse` or `lambo` with the adapter's native memory identifier.
- **`Citation`:** Attaches a memory to one or more `ElementId` values. Records a single-line summary of the claim, the recorder name, and a confidence score.
- **`Flag`:** Raised when an evidence source detects a breaking or review change. Carries the memory reference, change fact identifiers (`vc2_`, `lc2_`, `sc2_`), severity, versions, and evidence text.
- **`Proposal`:** Generated by a model during re-check. Recommends an action (`correct`, `retire`, or `keep`), along with a rationale and replacement text.
- **`Decision`:** Records human sign-off on a proposal. Captures the chosen verdict, optional edits to replacement text, reviewer identity, and timestamp.

## Flagging

Flag evaluation runs in [`src/check.rs`](https://github.com/nrynss/doyle/blob/main/src/check.rs). It compares changes between two versions of an evidence source against all registered citations.

When an evidence source reports a change, Doyle checks if any citation references the modified element or its ancestors.

Doyle categorizes flags by change severity:

- **Breaking changes:** Raise a `breaking` flag. For example, removing an endpoint or widening a COBOL field creates an immediate hold.
- **Review changes:** Raise a `review` flag. Inferred behavior shifts, like new pagination limits or changed file paths, require operator attention.
- **Additive changes:** Safe additions raise no flags. Adding a new optional endpoint or non-conflicting field leaves existing citations untouched.

A settled flag stays closed across checks. It reopens only when a brand new change fact touches its cited elements.

## The State Store

Doyle persists state in [`src/core/store.rs`](https://github.com/nrynss/doyle/blob/main/src/core/store.rs). It avoids heavy external databases.

All data resides in a local `.doyle/` directory as append-only JSON Lines files:

- **`citations.jsonl`:** Append log of all recorded citations.
- **`flags.jsonl`:** Append log of all raised change flags.
- **`proposals.jsonl`:** Append log of all model-generated repair proposals.
- **`decisions.jsonl`:** Append log of all human verdicts.

Every record is plain text. Developers can inspect state with standard tools like `jq` or diff files in git.

On startup, Doyle loads all four logs into memory. If a crash leaves a truncated line at the end of a file, Doyle logs a warning and loads valid records.
